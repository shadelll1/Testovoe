# orders-sync — мини-синхронизатор заявок

Забирает «сырые» заявки из `https://test.ooobs.ru/api/orders`, приводит телефоны к `+7XXXXXXXXXX`,
отбрасывает невалидные, схлопывает дубли по телефону и отдаёт клиентов со статистикой.

**Живой URL:** https://orders.добрострой23.рф/api/clients
(`https://orders.xn--23-9kcl0a2abaqbkm.xn--p1ai/api/clients`, то же самое отдаёт `/`)

```json
{
  "clients": [{ "name": "Иван П.", "phone": "+79991234567", "email": "", "amount": 5000 }, ...],
  "stats": { "received": 17, "unique": 8, "duplicates_merged": 5, "invalid_dropped": 4 }
}
```

## Эндпоинты

| Метод | Путь | Что делает |
|---|---|---|
| GET | `/api/clients`, `/` | синхронизирует с источником и отдаёт результат |
| POST | `/api/sync` | явный запуск синхронизации, ответ тот же |
| GET | `/health` | проверка живости |

## Правила

**Телефон.** Из строки берутся только цифры:
- 11 цифр с первой `7` или `8` → `+7` и последние 10 (`+7 999 123-45-67`, `8 (999) 123 45 67`, `79991234567`);
- 10 цифр → номер без кода страны, дописывается `+7` (`9005551212` → `+79005551212`);
- всё остальное — невалидно и отбрасывается: пусто, текст, обрезанный номер (`+7 999`, `123`), чужой код
  страны (`+1 …`), лишние цифры (добавочный номер).

**Дубли.** Из заявок с одним телефоном остаётся запись с наибольшим `amount`; при равных — более поздняя по
`created_at`. Даты сравниваются как моменты времени с учётом часового пояса, а не как строки. Если совпало и то
и другое — берётся встреченная позже в выдаче, чтобы результат был однозначным. Запись выигравшей заявки
отдаётся как есть (пустой email из других дублей не дозаполняется — правило «оставить запись»).

`amount` в виде строки (`"5000"`) читается как число, мусор — как 0. Клиенты идут в порядке первого появления
их телефона в источнике.

**Статистика:** `received` — элементов в ответе источника; `invalid_dropped` — с невалидным телефоном;
`unique` — клиентов в итоге; `duplicates_merged = received − invalid_dropped − unique`.

## Идемпотентность и хранение

Результат хранится в SQLite, телефон — первичный ключ таблицы клиентов: дубль в хранилище невозможен
структурно. Каждая синхронизация — чистая функция от ответа источника, а снимок в базе заменяется целиком в
одной транзакции. Поэтому повторный запуск по тем же заявкам даёт байт-в-байт тот же ответ, а изменения
в источнике (новая заявка, исправленный номер) отражаются сразу. Параллельные синхронизации идут по очереди.

Если источник недоступен или вернул не JSON-массив, база не затирается: `/api/clients` отдаёт последний
сохранённый результат с заголовком `X-Data-Stale: <время синхронизации>`, `/api/sync` — 502.

## Запуск

```bash
python -m venv .venv && .venv/Scripts/pip install -r requirements-dev.txt   # Linux: .venv/bin/pip
.venv/Scripts/python -m pytest
.venv/Scripts/python -m uvicorn app.main:app --port 8000
```

Или `docker compose up --build`.

Настройки — переменные окружения (см. `.env.example`): `SOURCE_URL`, `DB_PATH`, `SOURCE_TIMEOUT`, `PORT`.

## Деплой

Виртуальный хостинг Beget: Passenger запускает WSGI-приложение из `passenger_wsgi.py` (FastAPI — ASGI,
переходник [a2wsgi](https://github.com/abersheeran/a2wsgi)). Python 3.12 — портативная сборка
python-build-standalone в папке сайта, зависимости — в `venv` рядом. HTTPS — бесплатный сертификат хостинга.

```
~/orders/
  passenger_wsgi.py  app/  requirements.txt   код из git
  python312/  venv/                            Python и зависимости
  data/sync.sqlite3                            результат синхронизации
  public_html/.htaccess                        PassengerEnabled On, PassengerPython ~/orders/venv/bin/python
```

Обновление: `git archive HEAD | ssh <хостинг> 'tar -x -C ~/orders && ~/orders/venv/bin/pip install -r ~/orders/requirements.txt && touch ~/orders/tmp/restart.txt'`.

Для сервера с Docker — `Dockerfile` и `docker-compose.yml` (`docker compose up --build`, порт 8000).

## Секреты

У сервиса нет секретов: источник публичный, токенов не нужно. Вся конфигурация — переменные окружения;
`.env` в `.gitignore` и `.dockerignore`, в репозитории только `.env.example`. На хостинге переменные задаются в
`.htaccess` сайта (`SetEnv`), в Docker — через `env_file`; появись токен источника, он пойдёт туда, а не в код,
образ или git.
